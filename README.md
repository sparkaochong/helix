# Helix

用遗传规划挖掘因子表达式 + 深度学习合成，预测 A 股短周期"触及"事件。

**预测目标**

> D0 收盘后用截至 D0 的信息计算因子 → D+1 开盘买入 → **D+2 最高价是否触及 D+1 开盘价 × 1.08**

```
D0 收盘          D+1 开盘          D+2 盘中
  │                │                 │
  └─ 特征计算       └─ 建仓           └─ high ≥ entry × 1.08 ?
```

---

## 三个决定成败的实现细节

这类项目最常见的失败不是模型不够强，而是标签或切分里藏了未来函数，跑出漂亮的回测然后实盘归零。Helix 在这三处做了明确处理：

| 问题 | 错误做法 | Helix 的做法 |
|------|---------|-------------|
| **除权除息** | 用原始价算 `high[D+2]/open[D+1]` | 用后复权价（`*_hfq`）算比值。原始价只用于和当日涨跌停价比较 |
| **一字涨停买不进** | 把这些样本当正样本留在训练集 | D+1 开盘价 ≥ 当日涨停价的样本**直接剔除**（标签置为未定义，不是 0） |
| **ST 判定** | 用当前股票名过滤 | 用 `namechange` 历史还原**每个交易日当时**的股票名 |

此外：

- **停牌** → 标签未定义（NaN），不是 0。D+1 或 D+2 停牌就无法观测结果。
- **切分隔离** → train/valid/test 之间强制 `embargo_days` 间隔。D0 的样本在 D+2 才结算，紧邻切分会让训练集尾部泄漏到验证集头部。配置加载时会校验 `embargo_days ≥ touch_offset + 1`，不满足直接报错。
- **挖掘只看最早的训练块** → GP 搜索限制在第一个 `train_days` 窗口内，之后的数据全部留给 walk-forward。在全历史上挖因子再"验证"是自欺欺人。

## 两条数据通路

Helix 有两个后端，共用同一套算子、指标、切分纪律和 GP 引擎。

### A. 面板通路（Tushare 全市场）

从 Tushare 自建 `(交易日 × 股票)` 面板，自己造基础字段。时序算子可用。适合从零开始做全市场研究。

### B. 事件表通路（长表，如 argus_quant）

输入是「每天若干只入选股票 + 数百个已算好的特征」的长表。每天的行压进 `0..n_t-1` 槽位，得到 `(T, N_max)` 网格——截面算子照常有效。

**槽位 j 在不同日子是不同公司**，所以时序算子在这个布局下毫无意义（`ts_mean(x,20)` 会把二十家不相干的公司平均起来）。`build_event_pset` 用硬断言拒绝任何时序算子进入，不是靠注释提醒。

这条通路的产出是**因子列**：`helix/gp/export.py` 生成一个只依赖 numpy/pandas/pyarrow 的独立脚本，直接在训练机上给数据集追加列并输出 IC/ICIR 报告。

```bash
python scripts/mine_argus.py --input train.parquet --out artifacts \
       --n-features 70 --rounds 5 --neutralize-base 8
# 然后把 artifacts/apply_factors.py 拷到训练机
python apply_factors.py --input train.parquet --output train_with_factors.parquet
```

## 挖出来的因子必须"有增量"，而不只是"有 IC"

这是本项目最重要的一条经验，来自一个真实的负面结果。

第一轮在 argus_quant 上挖出的因子 `gp_000`：

```
原始                        IC +0.0873   ICIR +0.709   正 IC 77.4%
对自身最强输入正交化后        IC +0.0453   ICIR +0.436
对自身全部三个输入正交化后    IC -0.0063   ICIR -0.112   ← 归零
```

它只是三个已有列的线性混合，而那三列**本来就在训练集里**。挂上这一列，下游模型什么也得不到——它自己就能学出这个组合。

所以默认的适应度是**残差 IC**：`helix/gp/neutralize.py` 把因子对基列按日投影，只有解释了基列解释不了的部分才得分。`--neutralize-base N` 指定用 IC 最强的 N 个源列做基，`--rounds K` 让每一轮再把已找到的因子加进基，逼出互不相关的因子。

两个实现细节值得知道：

- **幅度守卫不可省略。** 下游指标基于秩、尺度无关。一个被完全解释的因子残差只剩 `1e-16` 的浮点噪声，但那噪声**仍然保留原始排序**，会被当成信号打出分来。残差占比过小的交易日直接判为已解释，返回 NaN。
- **投影在秩空间是线性的**，移除不了基列的单调非线性变换。存活的因子是待验证的候选，不是独立性的证明——上线前要对真实特征集复核增量。

## 在 argus_quant 上的结论：GP 因子没有增量

残差 IC 是**必要条件而非充分条件**。终审是模型消融：同样的行、切分、超参和种子，只比较特征集加不加因子列。`scripts/ablate_factors.py` 做这件事。

基线：459 个已有特征 + XGBoost(400 棵树)，样本外 2024-09-10 ~ 2026-07-24。

| 因子集 | IC | top20 命中率 | lift |
|---|---|---|---|
| 基线（459 列） | +0.09936±0.00119 | 35.51%±0.63 | 2.106±0.038 |
| + 17 个因子（8 列中性化） | +0.09905±0.00069 | 35.51%±0.73 | 2.106±0.043 |
| + 12 个因子（40 列中性化） | +0.10007±0.00097 | 35.46%±0.23 | 2.103±0.014 |

**两组因子的增量都在种子噪声内。** 加不加，模型表现一样。

原因是结构性的，不是调参没调好：

> **GP 因子是已有列的确定性函数，不引入新信息，只是重新参数化。** 对一个有 459 列、400 棵树的梯度提升模型，那些结构它自己就能学出来。

GP 在这类场景下唯一的独特贡献本该是**截面算子**——树模型逐行处理，算不出 `cs_rank` / `cs_zscore`。但这个数据集本身已经带了 `*_rank` 版本的列，这个缺口是堵上的。

**什么情况下才值得再挖：**

1. 引入**新的原始信息**（盘口、资讯、其他频率），而不是重组已有列；
2. 下游模型受容量限制（线性/小模型），此时人工结构确实有用；
3. 数据集缺少截面算子构造的列；
4. 换一个目标——当前目标可能已被现有特征吃透。

**判定门槛**：基线的种子间标准差是命中率 0.63pp、lift 0.038。任何因子集要算真有用，至少要超过 2σ ≈ **命中率 +1.3pp / lift +0.076**。单种子跑出来的差值不可信——首次单种子消融显示命中率 -1.0pp，三种子下实际是 +0.004pp。

## 同一个结论的第二个例子：strategy_name 也没有增量

`strategy_name` 是字符串列，而 `feature_columns()` 只收 int/float，**所以它从来没进过模型**。它六个取值的基准命中率差 2.6 倍：

| 策略 | 基准命中率 | 行数 |
|---|---|---|
| 趋势股跟随（60日动量+MA过滤+XGBoost） | **21.71%** | 72,907 |
| 板块热度 XGBoost | 18.04% | 105,124 |
| 超跌反包 | 16.56% | 21,188 |
| 高低切 XGBoost | 16.31% | 141,296 |
| 阳线动量 | 15.37% | 140,219 |
| 主线跟随 | **8.24%** | 136,682 |

看起来像白捡的信号。`ablate_factors.py --onehot strategy_name` 编码成六列，同样的行、切分、超参、三个种子：

| | IC | top20 命中率 | lift |
|---|---|---|---|
| 基线（459 列） | +0.09936±0.00119 | 35.51%±0.63 | 2.106±0.038 |
| + strategy_name 六列 | +0.10051±0.00039 | 35.65%±0.11 | 2.114±0.006 |
| **增量** | +0.00115 | **+0.14pp** | +0.008 |

门槛是 +1.3pp，实测 +0.14pp，**四个指标全部落在种子噪声内**。基准率差距是真的，但模型早就从别的列里把它推出来了——六个策略各有各的选股逻辑，那些逻辑依赖的量价形态本来就在 459 列里。

**这和 GP 那次是同一个结论的两种形态：确定性的重新编码拿不到增量，不管它是 GP 表达式还是分类变量 one-hot。** 459 列已经把这张表内可得的信息占满了。要有增量，只能引入表外的新信息（上面条件 1），而不是把表内的东西换个写法。

一个没有定论的观察：加上这六列之后**种子间标准差全线塌了**（命中率 ±0.63 → ±0.11，lift ±0.038 → ±0.006，IC ±0.00119 → ±0.00039）。机制上说得通——模型不必再从噪声代理里自己发现那个分层，而不同种子发现的方式不同。但三个种子估出来的标准差本身误差约 40%，四个指标又高度相关，**这不足以下结论**，而且均值没动。记在这里是因为它便宜到值得复核，不是因为它已经成立。

## 可成交性核验：argus_quant 的标签确实没有剔除买不进的样本

面板通路把「D+1 开盘价 ≥ 涨停价」的样本判为标签未定义，`tests/test_labels.py` 逐条钉死。事件表通路用的是 argus_quant 自带的标签，所以这条保证只能核验、不能假设。

表里没有 D0 收盘价，涨停价靠 `base[D+1] = open[D+1] / (1 + label_open_gap)` 反推，再按板块乘 10%/20%/30%（`scripts/fillability.py`）。这个 `base` 是 **`pre_close[D+1]`**，不是 D0 原始收盘价——而 `pre_close` 正是交易所报涨停价的基准，除权日两者能差一整笔分红（见下一节）。反推本身过了两道独立校验：

| 校验 | 结果 |
|---|---|
| `base[D+1]` 由 gap 推 vs 由 `label_d1_pct_chg` 推 | 中位差 2.8e-7，p99 9.2e-7 |
| 被标记样本满足 `open[D+1] == high[D+1]`（开盘即涨停当天涨不上去） | 99.52% / 2,933 行 |

**核验结果：确实没剔。** 2,933 行（0.475%）D+1 开盘即涨停，标签 NaN 比例 **0.00%**，这批的命中率 **37.47%**，是可成交样本（15.15%）的 2.5 倍。

但影响比预期小得多。`scripts/fill_impact.py` 把同一批预测按三种口径重算（3 种子 × 2 训练口径）：

| 口径 | top20 命中率 | lift |
|---|---|---|
| as-is（买不进的也算赢） | 35.51%±0.64 | 2.106±0.038 |
| **fill-aware（买不进的当没成交剔掉）** | **35.27%±0.66** | **2.104±0.039** |
| queue-deeper（只在可成交票里取 top20） | 35.24%±0.59 | 2.102±0.035 |
| 训练集也剔除后 fill-aware | 35.62%±0.58 | 2.125±0.034 |

这些票**确实集中在榜首**——占 top20 的 1.95%，是池内占比 0.45% 的 4.3 倍，方向和担心的一致。但绝对量太小：20 个仓位里平均 0.39 个买不进，命中率只掉 **0.24pp**，远在种子噪声（±0.64pp）之内。

**lift 几乎纹丝不动（2.106 → 2.104）**，因为剔掉这批票的同时基准率也从 16.86% 降到 16.76%，分子分母同向移动。排序质量没被这个缺陷污染（但排序质量本身不等于收益，见「成本回测」）。

`queue-deeper ≈ fill-aware` 还说明：把买不进的替换成下一名，什么也补不回来——替补的命中率就是池子的正常水平。

**结论：缺陷真实存在，但对结论无影响。** 诚实的可成交数字是 **35.3% / lift 2.10**，而不是 35.5% / 2.106。

已知盲区：2,231 行 gap≈+5% 可能是 ST（涨停幅度 5%，本表无股票名历史，分不出来）。上界检验——全部算成买不进，池子基准率变化从 -0.106pp 走到 -0.165pp，不翻转。

## 停牌核验：这一条 argus_quant 是对的

`label_d2_hit_8pct` 在全部 617,416 行上**零 NaN**。正确处理停牌的标签不该是这样——D+1 停牌进不去，D+2 停牌看不到结果，两种都该是未定义。所以要么池子上游剔了，要么停牌被静默当成了 0（那会**低估**命中率，方向和买不进那条相反）。

`scripts/check_suspension.py` 用 Tushare `suspend_d`（全天停牌，2021-10 ~ 2026-10 共 41,283 条 / 1,480 只票，与池内交集 1,089 只）按交易日历映射每行的 D+1、D+2。

**结论是剔了，不是填 0。** 但零本身不构成证据——匹配写错也返回零。所以脚本的主体其实是那个**正对照**：同一套查表逻辑在管线没理由过滤的偏移量上必须有命中。

| 偏移 | 命中行数 | 占比 |
|---|---|---|
| D-10 | 2,292 | 0.371% |
| D-1 | 351 | 0.057% |
| D+0 | 35 | 0.006% |
| **D+1** | **0** | **0.000%** |
| **D+2** | **0** | **0.000%** |
| D+3 | 230 | 0.037% |
| D+10 | 947 | 0.153% |

其他偏移共命中 7,546 行，只有该被过滤的两个是零。脚本里这条是硬断言：正对照全零直接 `SystemExit`，不让「零」被当成好消息。

再从另一路数据独立重建：抓 79 个交易日的全市场原始行情（399,625 根 K 线）+ 复权因子，比对落在窗口内的 32,146 行——

- **日历 D+1、D+2 的行情缺失 0 行**。管线若是「跳过停牌日取下一根 bar」，这里必然非零，标签窗口就错位了。
- 表内 `label_px_d1_open` / `label_px_d2_high` / `label_px_d2_close` 与原始价 **100.0000%** 相同，中位相对差 0。
- 用原始价重算 `high[D+2] >= open[D+1]×1.08`，与表内标签 **100.0000%** 一致。

标签就是它声称的那个东西。

**顺带查出的两件事：**

1. **标签用原始价算 D+1→D+2 的比值，没做除权调整。** 0.118% 的行在这两天之间除权除息，其中 38 行有 1 行在后复权口径下结论不同（原始价口径 100% 吻合，后复权 97.368%）。方向是低估命中率——除权当天价格自然下挫，但你收到了分红。折算全表约 0.003% 的行被错标，比种子噪声小三个数量级。

2. **35 行（0.0057%）在 D0 当天全天停牌却仍被选进池子。** 不影响标签（D+1/D+2 都正常交易），但说明选股侧没有过滤 D0 自身。已记录，未处理。

## 成本回测：lift 2.10 和 CAGR −47% 可以同时成立

命中率 35% 对 17% 的基准是真的排序能力。它**不是**收益。`scripts/backtest_argus.py` 把同一批预测算成钱——打分逻辑直接 `from fill_impact import`，特征、切分、种子、模型全部复用，所以任何差异都只来自记账。

成本按 A 股法定口径：佣金 2.5bp、过户费 0.1bp（双边），印花税 5bp（仅卖出，2023-08-28 减半后的税率，脚本对早于该日的测试窗口直接报错退出）。净收益是乘法而非减法：`(1+g)(1−sell)/(1+buy) − 1`。资金按 `overlap = 2` 拆分。仓位是 fill-aware 的：提交 20 单，开盘涨停的那些当没成交剔掉（平均实际建仓 19.61/20）。

3 种子，样本外 431 个交易日，命中 35.27%、基准 16.76%、lift 2.104、IC +0.099：

| 退出假设 | 滑点 | 净收益/笔 | CAGR | Sharpe | 最大回撤 |
|---|---|---|---|---|---|
| 触及即成交（标签口径） | 0bp | **−0.469%±0.067** | −46.7%±4.7 | −2.10±0.30 | −69.8% |
| 触及即成交 | 10bp | −0.668%±0.067 | −58.5%±3.6 | −3.00±0.30 | −80.0% |
| **全部持到 D+2 收盘** | 0bp | **+0.378%±0.067** | +51.6%±12.3 | 1.35±0.21 | −32.8% |
| 全部持到 D+2 收盘 | 10bp | +0.178%±0.066 | +17.8%±9.5 | 0.63±0.22 | −34.0% |
| 全部持到 D+2 收盘 | 20bp | −0.023%±0.066 | −8.4%±7.4 | −0.09±0.24 | −37.9% |

符号在三个种子上全部一致。**按预测目标字面执行是亏钱的。**

原因在收益分解里，不在成本里：

| | 命中组持到 D+2 收盘 | 未命中组持到 D+2 收盘 |
|---|---|---|
| top20 | **+10.07%** | **−4.58%** |
| 池内全样本 | +9.03% | −1.52% |

选股选出的是高波动动量票，**两侧都被放大**。+8% 止盈把唯一赚钱的那一侧削平（命中组本可以跑到 +10.07%），亏的那一侧却任其奔跑（−4.58%，是池子平均的 3 倍）。日胜率也印证：止盈口径 46.6%，持到收盘 53.1%。

**lift 度量的是排序，不是赔率。** 排序能力真实存在且已被多重核验，但一个把赢家封顶、放任输家的退出规则能把它变成负期望。这是本项目第二条重要经验，和「残差 IC 不等于增量」是同一类错误的两种形态。

**已知未建模的部分（都指向乐观）：**

- **D+2 跌停卖不掉**没有建模。未命中组的尾部到 1% 分位是 −14.4%，跌停在这个尾部里不罕见，所以「全部持到 D+2 收盘」这条实际上做不到。这是 Sharpe 1.35 面前最大的问号。
- 滑点余量很窄：收盘口径的盈亏平衡点约在**单边 19bp**。
- 分解数字是按日平均再平均的，和命中率不构成算术恒等（低命中率的日子未命中组也更差，存在负协方差）。
- 池子仍是 6 策略预筛后的（基准 16.76%），不是全 A 股。

**直接的方法论后果**：如果实际策略是持到 D+2 收盘，那么用 `P(触及 8%)` 排序就不是对口的目标——应该直接回归 `label_d2_return`。已验证，见下一节：在集中持仓下反而更差。

## 持仓规模：唯一一个把曲线形状改好的旋钮

止盈档、滑点、置信度门槛都试过，没有一个能把负期望翻正或者把回撤显著压下去。**持仓只数可以。** 同一套排序摊到更多票上，是同一份 edge 配更小的方差——预测的东西没变，曲线的形状变了。

`--hold-grid` 在一次训练里扫完所有持仓档（模型是贵的那一半，和持仓数无关），3 个种子、样本外 431 个交易日、持到 D+2 收盘、单边 10bp：

| 持仓 | Sharpe（分类） | 最大回撤 | 终值 | 日胜率 | Sharpe（回归 D+2 收益） |
|---|---|---|---|---|---|
| 1 | +0.13±0.28 | −72.8% | 0.70 | 45.5% | −0.03±0.35 |
| 2 | +0.94±0.41 | −56.3% | 2.22 | 49.8% | +0.53±0.18 |
| 3 | **+1.40±0.19** | −45.4% | 3.04 | 50.2% | +0.50±0.17 |
| **4** | **+1.39±0.02** | −41.1% | 2.76 | 51.0% | +0.71±0.34 |
| 5 | +1.26±0.16 | −40.5% | 2.35 | 51.7% | +0.79±0.37 |
| 8 | +1.32±0.23 | −37.1% | 2.31 | 53.5% | +1.00±0.39 |
| 12 | +1.01±0.32 | −35.8% | 1.78 | 52.7% | +0.96±0.24 |
| 20 | +0.67±0.13 | −34.0% | 1.35 | 51.6% | +1.02±0.08 |

三件事同时成立：

1. **持仓 1 是灾难**（Sharpe 0.13，回撤 −72.8%，终值 < 1）。这不是噪声，它有机制：`P(触及 8%)` 对 D+2 收盘收益的 IC 是 **−0.064**，也就是说这个分类器的最强信念恰好是它按收益算最差的一只。只买第一名等于把负相关的那一端全额下注。
2. **回撤随持仓数单调变浅**（−72.8% → −34.0%），但**日胜率几乎不动**（中位 50%~53.6%）。分散改的是方差，不是出手的对错率。
3. **回归 `label_d2_return` 没有救回集中持仓**。它在 hold≥8 上追平甚至反超，但在 hold≤4——也就是真正要用的那一档——始终不如分类器。上一节那条方法论推论到此为止。

**已落地的规格改动：持仓从 TOP1~TOP2 改成 TOP4**，候选表仍给 TOP5（`--signal-k` 要留出替补深度，涨停买不进的名次要能往下顺延）。

取 4 而不是 3，是因为 3 的 Sharpe 高 0.01 而种子标准差是它的 9 倍（±0.19 vs ±0.02）；4 是全表最稳的一档。

**必须说清的保留**：hold 是在测试集上看着结果挑的。「1 很差」「≥3 好过 ≤2」「票越多回撤越浅」这三条是有机制的结构性结论；**峰值恰好落在 3~4 这件事本身是挑出来的**，不要当成样本外保证。

### 和那张对照表比，达标了吗——没有

对照表的口径是 28 个交易日（71.4% 和 60.7% 同时精确只在 n∈{28,56,84,112} 成立，即 20/28 和 17/28）。**最大回撤是观测窗口上的最小值，只会随窗口变长而变深**，所以 28 天的 −7.61% 和 431 天的 −41.1% 不是同一个量。`scripts/window_stats.py` 把长曲线切成 28 天滚动窗口来消掉这个混淆（窗口高度重叠，只做分布描述，不做检验）：

| 持仓 | 累计 ≥ +25% | 正收益日 ≥ 71.4% | 回撤 ≥ −7.61% | 三条同时 |
|---|---|---|---|---|
| 2（原规格） | 25.41% | 2.15% | 1.57% | 0.99% |
| 3 | 24.92% | 3.47% | 4.62% | 1.65% |
| 4（新规格） | 20.87% | 3.30% | **5.45%** | 1.49% |

- **+25% 累计收益本来就在噪声里**：五分之一的 28 天窗口就能达到，最好的一个是 +123.9%。这条从来不是差距。
- **−7.61% 回撤靠分散够得着**：持仓 2 只有 1.57% 的窗口能做到，持仓 4 提到 5.45%（p95 正好是 −7.6%）。改持仓真正买到的是这一条。
- **71.4% 正收益日在任何持仓档上都够不着**：中位数稳定在 50%，最好的窗口 78.6%，但只有 3.3% 的窗口能到 71.4%。一个日胜率 50~53% 的策略，28 天里出现 ≥20 个正收益日的概率是 1.8%~4.3%（`binom.sf(19, 28, p)`），和实测的滚动频率对得上。

结论：对照表的三个数字，**在我这条曲线上是一个 1/25 到 1/30 的 28 天窗口**，而且是被挑出来的那一个。它不构成「别人的模型比我的好」的证据，也不构成我已经追平的证据——**正收益日那一条是真差距，且不是持仓规模能解决的**（分散改方差不改胜率）。要动它得换预测目标，不是换仓位。

对照方自己也标注了「N15 Top4 近期很好，但前段几乎没有收益，明显存在短窗挑排名风险」——那正是这一节在量化的东西。

## 架构

```
Tushare ──► ParquetStore ──► Panel (T×N)  ──► base fields (~26)
                                 │                  │
                            universe mask           ▼
                                 │            GP 搜索 (DEAP)
                                 ▼                  │
                            touch label      factors.json (可读表达式)
                                 │                  │
                                 └────────┬─────────┘
                                          ▼
                              截面标准化 → GRU 合成 → walk-forward
                                          ▼
                                    OOS 预测 → 回测
```

面板是 `(T, N)` 的二维数组：行是交易日，列是股票。时序算子沿 axis 0，截面算子沿 axis 1 —— 这个布局是 GP 能跑得动的前提。

### 模块

| 路径 | 职责 |
|------|------|
| `helix/data/` | Tushare 增量下载、parquet 存储、面板构建、时点股票池、事件表槽位面板 |
| `helix/labels/` | 触及标签，含可成交性过滤 |
| `helix/features/operators.py` | 面板算子（`ts_*` 严格后视，`lead` 仅供标签使用） |
| `helix/features/base_fields.py` | GP 的原料字段 |
| `helix/gp/` | 类型化算子集、适应度、中性化、特征预筛选、进化循环、因子库与导出 |
| `helix/dl/` | 序列构造、GRU 合成模型、walk-forward 训练 |
| `helix/eval/` | 日频 AUC/gini、IC/ICIR、precision@k、交易级回测 |
| `helix/splits.py` | 带 embargo 的 walk-forward 切分 |

## 关键设计说明

### GP 适应度：两个窗口，不是一个

搜索窗口内部再切成 **fit 段**（驱动进化）和**隔离后的 sel 段**（决定去留）。进化最大化 fit 段的 `|gini|`；一个因子只有在 sel 段上**符号仍然一致且为正**才会被保留。在同一批行上既优化又筛选，是 GP 流水线产出"样本内绝美、样本外归零"因子的标准姿势。

因子的符号是自由参数：gini 为 `-0.2` 的因子取负后和 `+0.2` 一样好用，所以适应度用绝对值，符号单独记录在 `factors.json` 里。

### 为什么是日频 AUC 而不是池化 AUC

所有指标都**按交易日算完再平均**，从不跨日池化。池化会让"知道哪些周整体好做"的因子拿高分，但策略要做的是**当天在几千只票里选 20 只**，跨日信息毫无用处。早停也盯日频 gini，不盯 loss。

### 去相关

GP 会收敛到一堆近乎同义的表达式。名人堂按 sel 段表现排序后，贪心地按截面秩相关（阈值 `max_abs_corr`）去重再交给网络。喂 24 个同一个想法的副本，效果不如喂 8 个真正不同的。

### 截面标准化的 population 必须是股票池，不是标签有效性

标准化用 `universe`（D0 收盘即可确定）而**不是** `labels.valid`。后者额外依赖 D+1 是否一字涨停、D+1/D+2 是否停牌 —— 用它当 population，未来信息就会影响 D0 特征的均值和标准差。而且它会让最后两行全是 NaN，正好是实盘打分需要数值的地方。

### 实盘打分

```bash
.venv/bin/helix score --date 20260810 --top 30
```

打分的候选集是 **D0 当天的股票池**，不是 `labels.valid` —— 最新一根 K 线的特征在 D0 收盘时已经完整，但标签必然未定义（D+2 还没发生），这正是要预测的东西。

checkpoint 里记录了训练时的因子列表，重新挖过因子之后再拿旧模型打分会直接报错，而不是给你一串看起来合理的概率。

### 为什么用 GRU 不用 Transformer

回看窗口 20 天、输入二十来个因子、正样本率个位数百分比 —— 注意力机制没什么可注意的，只会更快过拟合。循环结构能抓"这个因子连涨了一周"这种形态，正好是两日触及关心的信息。

停牌日在序列里会变成 0，和"真的很平均"无法区分，所以额外拼了一个 `traded` 通道让网络能分辨。

### 回测的退出假设

和标签严格一致：触及则按目标价成交（+8%），未触及则按 D+2 收盘价离场。只报命中率会掩盖真正的问题 —— 没命中的那批往往是低开砸下去的。

净值曲线按 `overlap = touch_offset - entry_offset + 1 = 2` 拆分资金（每天开新仓时上一批还没平），所以不是逐日收益的简单累加。

## 尚未包含

- **模型定期重训**：`score` 用的是最后一折的模型，随着时间推移会越来越旧。没有自动判断"该重训了"的机制。
- **成本模型**：面板通路只有固定的双边 bps；事件表通路（`scripts/backtest_argus.py`）按法定费率 + 滑点网格算，但两条都没有冲击成本、没有按成交量约束仓位、没有把 D+2 跌停当成卖不掉。
- **指数/行业中性化**：因子未做行业中性，选出来的票可能高度集中在少数行业。

## 一个必要的预期管理

这个框架解决的是**方法论正确性**问题 —— 它保证你测出来的数字是真的。它不保证数字好看。

D+2 单日触及 +8%，在剔除 ST（5% 涨停会让标签几乎不可达）后的全 A 股上，正样本率大概率是个位数百分比。先跑 `helix prepare` 看 base rate，再看 `helix backtest` 的 `lift` —— **lift 是第一个该看的数字，但不是最后一个**。lift 接近 1 说明模型没有信息，无论命中率看起来多高；而 lift 显著大于 1 也不保证赚钱，因为它只度量排序，不度量赔率。argus_quant 上 lift 2.10 对应的净收益是 **−0.47%/笔**（见「成本回测」）。两个都要看。
